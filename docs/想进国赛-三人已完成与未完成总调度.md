# 想进国赛｜三人已完成与未完成总调度

更新时间：2026-10-11

这份文档按我们前面“想进国赛”那轮思路重新整理。不是看谁功能做得多，而是看：一件真实任务能不能从判断问题一直走到成果复核。

## 一、我们参考的三个 Agent 作品

这次只抓三个最有用的参照方向：

| 参照作品 | 我们学什么 | 对我们现在最直接的要求 |
| --- | --- | --- |
| **Vite Vere** | 看懂用户当前遇到的情况，再给很细的下一步，不让用户自己重新想流程 | 卡住时上传图片/视频后，系统必须知道用户卡在哪个任务、哪一步，并给出下一步操作 |
| **Apollo** | 研究、分析、协作汇总要有来源和状态，不能只给一段“像答案”的文字 | A 的判断必须带来源，B 的动作必须能追到 A 的差距，总控要保存版本和状态 |
| **Konveyor** | 根据知识缺口和当前能力给不同学习路径，不是所有人都走同一套课程 | 先试做，再判断真实能力；不会的人给细步骤，会的人不要重复学基础 |

之前还看过“医链智擎”这类国内获奖项目，它给我们的提醒是：先把真实需求、真实材料和真实问题弄清楚，再谈功能。这里不把它算进上面三个 Agent 参照，只作为国内赛事场景判断的补充。

从这些作品里，我们留下四条最重要的标准：

1. **先试做，再判断能力。**
2. **每一步都要写清：改哪里、为什么改、怎么做、交什么、怎样算完成、卡住怎么办。**
3. **成果提交后重新复核，不是点“完成”就结束。**
4. **遇到突发安排，只改受影响的部分，不把整个计划推翻。**

> 说明：`phucmanh146-dot/shanganya` 的 `feature/total-dispatch` 是这次总调度展示分支。三个人实际开发进度仍以 `phucmanh146-dot/shangan-ya` 里的职责分支为准。

# 二、A 同学｜诊断研究

A 负责回答：**现在到底差在哪里，为什么。**

## 已完成

| 已完成部分 | 现在已经有的内容 |
| --- | --- |
| 目标和标准 | 已经有任务名称、评审/交付标准、现有成果等输入结构 |
| 先试做 | 已经把“先试做一个小样本，再判断能力”加入方案 |
| 差距分析 | 已经设计差距矩阵、P0/P1/P2/P3、根因、现状和目标 |
| 资料依据 | 已经要求差距带来源、证据、参考和未知项 |
| 交接给 B | 已经明确每条差距后面要继续变成具体动作 |
| 交接给总控 | 已经明确诊断要有版本，新材料进来后要重新判断 |
| 突发情况 | 已经考虑不能因为临时事情把整个计划全部重来 |

## 未完成

| 未完成任务 | 为什么还不能算完成 | 完成标准 |
| --- | --- | --- |
| **真实 Diagnosis 生成** | 现在主要是方案和表格，仓库里还没有 A 自己独立的真实诊断模块提交 | 给一份真实材料和真实成果，能自动产出至少 3 条有证据的 gap |
| **原文定位** | 还不能稳定指出“哪一页、哪一段、哪个数据”有问题 | 每条 gap 都能回到原材料具体位置 |
| **试做后的能力判断** | 有“先试做”的设计，但还没有形成程序判断 | 试做结果能影响指导深度：不会/会一点/能独立做 |
| **真实资料检索** | 还没有把官网、参考作品、用户材料真正接到 A 的判断里 | 每条关键结论能看到来源，缺资料就明确写未知 |
| **新成果复核** | 这是当前最大的断点之一 | 用户交新成果后，A 能判断原 gap 是关闭、部分关闭还是仍未通过 |
| **新资料影响旧结论** | 新材料来了，旧结论是否失效还没真正跑通 | 能指出哪条旧判断被新资料改变，不影响的部分保持不动 |

### A 现在只做四件事

1. 用一个真实比赛材料 + 一个真实现有成果跑出第一份 Diagnosis。
2. 每条 gap 加上原文位置、来源、现状证据、目标条件和判断理由。
3. 把“先试做”接到真实能力判断里。
4. 做新成果复核，不合格的差距继续交给 B。

| **按能力调整步骤** | 已有规则，但真实试做结果还没接进来 | 同一任务对不同能力的人，步骤粒度明显不同 |

### B 现在只做四件事

1. 直接读取 A 的真实 gap，不再用手工假数据作为主要演示。
2. 每条任务写到“陌生人照着也能做”。
3. A 复核不通过时，只改没通过的那一部分。
4. 把正式状态交给队长总控，不再和总控各维护一套项目真相。

# 六、现在离“想进国赛”还差什么

我们现在不是从零开始。队长的总控底座已经比较完整，B 也有实质代码和排程能力，A 的方案也已经把问题想得比较细。

真正没做完的是这三件事：

**第一，A 的判断要从“设计好的表”变成真实诊断。**

**第二，B 的计划要从“自己能排”变成“根据 A 的真实差距来排”。**

**第三，队长要把三个人真正串起来，让一个真实任务从输入走到成果复核。**

参照那三个作品，我们最该学的不是“再加几个功能”，而是把一件事做到底：

> **真实材料 → 先试做 → 判断能力和差距 → 给具体动作 → 用户执行 → 卡住时定点救援 → 上传新成果 → 重新复核 → 只改剩余问题 → 最终验收。**

这条链跑通，才是下一阶段最有价值的成果。
